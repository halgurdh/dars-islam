## للمدارس والمعلمين والطلاب وأولياء الأمور

يمكن لأي شخص لعب أي لعبة كضيف دون حساب — يُحفظ التقدم (نقاط الخبرة، المستويات، السلاسل، الأوسمة) تلقائيًا على ذلك الجهاز.

**الطلاب** — للانضمام إلى فصل دراسي، اطلب من معلمك رمز الفصل، ثم افتح **لوحتي** (مرتبطة في رأس الموقع) واستخدم نموذج "الانضمام إلى فصل". يؤدي هذا إلى مزامنة تقدمك مع قائمة معلمك، ويمنحك **رمز العائلة** (يظهر في لوحتك) لمشاركته مع أحد الوالدين.

**المعلمون** — افتح **لوحة المعلم** من رأس الموقع، سجّل الدخول ببريدك الإلكتروني (سيُرسَل إليك رابط دخول سحري عبر البريد، دون الحاجة لكلمة مرور)، ثم أنشئ مدرسة وفصلاً دراسيًا. شارك رمز الفصل مع طلابك. من هناك يمكنك عرض قائمة الفصل/لوحة المتصدرين وتعيين ألعاب معينة لفصلك.

**أولياء الأمور** — افتح **لوحة ولي الأمر** من رأس الموقع، سجّل الدخول ببريدك الإلكتروني، وأدخل رمز العائلة الذي شاركه معك طفلك. ستشاهد تقدمه (المستوى، السلاسل، الأوسمة) ويمكنك تحديد حد زمني يومي لوقت الشاشة وحظر ألعاب معينة.

## للمطورين (الاستضافة الذاتية / التشغيل على خادمك الخاص)

**➡️ راجع [SELF_HOSTING.md](SELF_HOSTING.md) للدليل الكامل** — إعداد Supabase (الواجهة الخلفية للحسابات/التقدم/المدارس)، Docker، GitHub Pages، وعمليات النشر على الخوادم التقليدية.

مرجع سريع:

```bash
npm install
cp example.env .env.local   # أدخل VITE_SUPABASE_URL / VITE_SUPABASE_PUBLISHABLE_KEY
npm run dev                 # التطوير المحلي (مركز wrapper + كل لعبة)
npm run build                # بناء الإنتاج → dist/
npm test                     # تشغيل مجموعة الاختبارات
```

يجمّع `npm run build` مركز wrapper وجميع الألعاب في مجلد `dist/` — مجلد
ثابت واحد، قابل للنشر في أي مكان يخدم الملفات الثابتة. يتواصل التطبيق مع
Supabase مباشرة من المتصفح؛ لا حاجة لتشغيل أي عملية خادم في الإنتاج.

بعد تشغيل ترحيلات SQL، هناك أيضًا إعدادان في **لوحة تحكم** Supabase (وليس SQL) مطلوبان قبل أن تعمل الحسابات:
- **Authentication → Providers**: تأكد من تفعيل البريد الإلكتروني (الرابط السحري)، وفعّل **Anonymous sign-ins** (مطلوب لتدفق انضمام الطلاب بدون بريد إلكتروني).
- **Authentication → Emails**: أعدّ مزوّد SMTP حقيقيًا قبل الاعتماد على هذا لأكثر من مجرد الاختبار — فالمرسل المدمج في Supabase له حدود صارمة لمعدل الإرسال.

**Docker** (أسرع طريقة للاستضافة الذاتية — يبني الموقع ويخدمه عبر nginx، ولا يعمل شيء آخر داخل الحاوية):

```bash
cp example.env .env   # ملاحظة: .env وليس .env.local — docker compose يقرأ هذا الملف
# أدخل VITE_SUPABASE_URL / VITE_SUPABASE_PUBLISHABLE_KEY في .env
docker compose up --build
# افتح http://localhost:8080
```

أو بدون compose: `docker build --build-arg VITE_SUPABASE_URL=... --build-arg VITE_SUPABASE_PUBLISHABLE_KEY=... -t dars-islam-games .` ثم `docker run -p 8080:80 dars-islam-games`. راجع [SELF_HOSTING.md](SELF_HOSTING.md) للتفاصيل (يتم تضمين هذه القيم وقت البناء، لذا تغييرها يعني إعادة بناء الصورة).

هيكل المستودع:
- `wrapper/` — موقع المركز العام (شبكة الألعاب، تسجيل الدخول، لوحات التحكم)
- `games/<name>/` — الكود المصدري وإعدادات Vite لكل لعبة
- `shared/` — الكود المشترك بين جميع الألعاب (عميل Supabase، تتبع
  التقدم، أدوات واجهة المستخدم المشتركة، الترجمة)
- `database/supabase/0001_init.sql` — مخطط Postgres/RLS/RPC الذي يجب
  تشغيله على مشروع Supabase الخاص بك
- `scripts/` — أدوات مساعدة للبناء والنشر

مجلدا `api/`/`database/schema.sql` هما واجهة خلفية قديمة من PHP/MySQL،
حلّت محلها Supabase — محتفَظ بهما للرجوع إليهما، ولا يستخدمهما التطبيق بعد الآن.
